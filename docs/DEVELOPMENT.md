## データと開発上の注意

会社 → 拠点 → 隊員・現場、会社共通取引先 → 利用拠点・現場、勤務枠 → 不変の公開版・編集可能な下書き → 配置・資格条件、という関係。内部利用者 → Google識別子・所属役割・隊員対応 → アプリセッションを別管理する。メールの一致だけで所属を作らない。

現行テストは固定の2026年10月4日を画面基準日として使用する。通常環境の期限・開始終了判定はサーバーの実時刻で行う。旧モックの固定G004と実利用者の識別子を混ぜない。会社や拠点IDは画面の選択だけでは認可されない。

マイグレーションは適用済みのSQLを変更せず、新しい連番ファイルで追加する。ランナーは適用済みチェックサムの変更を拒否する。API用DBユーザーにDDL・認証秘密テーブルへの直接アクセス・監査の改変権限を与えない。

## 目的と現在の段階

警備会社の配置・現場・隊員・勤怠などの管制業務を支援するクラウド型Webアプリを作る。
ユーザーは「くもかん」のような警備業界向けのサービスを参考に挙げているが、競合の仕様調査や同等機能の実装を完了したわけではない。
目指す構成は会社ごとにデータを分離するマルチテナントで、最初から全機能を作らず必要最低限から段階的に進める。

現在は画面の見た目を確認するモック段階。ユーザーはボタンが反応しなくてもよいと明示している。
管理者・管制向けの9画面と設定内の4カテゴリ、警備員向けの14画面を維持し、認証5・登録編集8ルートの入力・確認見本を追加した。合計36のURLを使い、検索・入力プレビューなど表示確認に必要な操作を一部動かせる。
初回の機能範囲は、隊員・現場の登録、配置の確定、本人の勤務予定表示までとユーザーに確認済み。ユーザーから要件確認と設計を進める指示があり、業務運用に関わる未決事項は確認しながら進める。

2026年10月8日の資料整理時には、ユーザーから「実装までは進まないでください」と指示された。その後、フロー・機能の漏れや不要なものを確認してモックを直す依頼を受け、見た目と確認経路だけを変更した。ボタンは表示のみでよいという方針を維持し、保存・認証・業務API・マイグレーション等の詳細機能は追加していない。実機能の実装開始には別途の依頼が必要である。

機能の詳細・業務ルール・権限表の案は、[初回実装の要件書 草案](requirements/MVP_REQUIREMENTS.md)にまとめた。ログイン・会社分離・権限を前提とし、勤務希望・出退勤・勤怠等は次期以降としている。範囲の確認済み事項と実装前の未決事項を区別しており、詳細な業務ルール・権限の決定や実装完了を意味しない。

保存項目と関係図は[初回のデータ設計案](requirements/MVP_DATA_DESIGN.md)にまとめた。現場と日別勤務、確定版と下書き版、過去配置と重複防止用の有効予約を分け、会社境界・同時確定の対策を設計している。業務ルールの回答を待つ部分があり、マイグレーション・業務API・RLS・認証の実装はまだない。

対象は交通誘導・施設警備とし、人数がそろってからの配置確定と4役割の基本権限を確認済み。2026年10月8日、本店・各支店に独立した初期登録枠10人を設け、担当者は個別にログインし、初回は本店からの支店追加・増枠に課金しない基本設計も確認した。登録枠は在籍・休職を数え、退職者は履歴を残して除く。追加回答で支店追加・増枠は本店所属会社管理者だけに許可し、取引先は会社共通で1件を登録して各拠点の現場から参照する方針を確定した。管制担当・閲覧者は所属拠点に関係する取引先に限定する。

全利用者の個人メール利用とGoogleログインの採用も確認済み。個人Gmail・会社Workspaceを許可し、会社管理者の二段階認証を必須、管制担当・閲覧者・警備員は推奨とした。全員のアプリセッションは本人の操作なし24時間・ログインから最長1か月で、先に到達した期限で失効する。招待は本人Googleメールへ発行から7日間有効なリンクを送り、再招待で旧リンクを無効にする。Google関連付け変更は会社管理者、管理者本人なら別の会社管理者、ほかにいなければ運営者が承認する。最初の会社管理者登録と全管理者利用不能時の復旧は、運営者が会社・本人を確認して対応する。

本人用Googleアカウントの準備状況、本人確認記録・不達等の招待/復旧の詳細手順、Google側の管理者MFA強制・確認方法、共通取引先の編集担当、異動後の履歴閲覧、資格条件、現場情報の公開期間等は未決事項に残している。

入力や選択を変更しても、DBには保存されない。設定のプレビューは同じ画面内のカテゴリ切り替えでは保持されるが、再読み込みで初期値に戻り、他の業務画面には反映されない。
通知スイッチや利用者の「招待準備の例」「停止」は表示例であり、通知・メール・利用者招待や停止は行わない。Googleアカウント自体の発行や停止を示すものでもない。
管理画面のヘッダー下で、モックであること、登録・保存・通知・出力を行わないこと、基準日時を表示する。警備員画面も、保存・送信・打刻・通知を行わないことと同じ基準日時を表示する。
