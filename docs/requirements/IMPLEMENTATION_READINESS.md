# 実装前レビューと不足資料の案内

作成日・更新日: 2026年10月8日（日本時間） / 版: 0.4

**確認結果: 初回の機能範囲と基本設計は整理されているが、業務の例外・認証運用・API/画面の具体的な契約に未決事項がある。今回の補足資料をそのまま承認済み仕様として実装せず、該当段階の判断を確定してからAI Agentへ渡す。今回は実装を行わない。**

調査対象はREADME、DEVELOPMENT、SECURITY、60項目のチェックリスト、初回要件書/データ設計案、管理者/警備員の業務フロー、フロントの画面・サンプル、既存API・DB接続・CI。既存の未コミット資料を前提にレビューした。画面の見た目の再検証や法的適合性の判定を行ったレビューではない。

## 1 整理できていること

- 初回はログイン・会社分離・隊員/取引先/現場・配置確定・本人予定。勤務希望・打刻・勤怠・報告・通知等は次期。
- 対象業務は交通誘導・施設警備。人数がそろってから確定し、一部だけ先に本人へ公開しない。
- 会社管理者・管制担当・閲覧者・警備員の4役割と、会社/拠点/本人の基本範囲。勤務開始後の変更は会社管理者。
- 本店と支店の独立した初期10人枠。在籍・休職を算入し、退職は履歴を残して枠から除外。担当者は個別ログイン、初回の支店追加・増枠は課金なし。
- 全役割のログインはGoogle OAuth 2.0とOpenID Connectに一本化することがユーザー確認済み。自システムのログインID・パスワード入力、保存、再設定、自社TOTP・復旧コードは採用しない。内部利用者IDと会社・拠点・役割・隊員対応は自システムで管理する。
- 許可するGoogleアカウントは個人Gmailと会社のGoogle Workspace。非Gmailかつhdなしの外部メールGoogleアカウントは初回対象外。会社管理者はGoogle側の二段階認証を必須とし、管制・閲覧者・警備員は推奨する。全役割のアプリログインは本人操作なし24時間で失効し、継続操作しても最長1か月とすることが確認済み。
- 招待は会社管理者が本人のGoogleメールへリンクを送信し、発行から7日間有効、再招待で旧リンクを無効にする。Google連携変更は会社管理者が承認し、管理者本人の変更は自社の別の会社管理者、他にいなければ運営者が承認する。最初の会社管理者登録と全管理者がログイン不能になった場合の復旧/交代は、運営者が会社・本人を確認して対応することが確認済み。
- 支店追加/登録枠増加は本店所属の会社管理者だけに許可する。取引先は会社共通で1件として管理し、各拠点の現場から同じ取引先を参照する。管制・閲覧者は所属拠点に関係する取引先だけ閲覧することが確認済み。共有取引先の編集担当と異動後の過去履歴閲覧は未決。
- 現場と日別勤務、下書きと公開版、配置履歴と重複防止予約を分ける設計。夜勤・同時確定・会社ID付き参照・RLS・再送への配慮。
- 既存APIのOrigin/CSRF/入力/容量/頻度制限、秘密の分離、検証コマンドと、モック/未実装の境界。

上記には確認済み要件と技術設計案が含まれる。承認の有無の正本は[要件書4章](MVP_REQUIREMENTS.md)。RLS、認証基盤、再送処理等がすでに実装されたことを示すものではない。

セッション期間の技術案: 最長1か月は作成時点の日本時間（JST）の翌月同日時、同日がない月は月末同時刻として算出し、UTCの日時で保存する。本人操作でアイドル期限を更新しても絶対期限は延長しない。ポーリング等の自動更新ではアイドル期限を更新しない。これは確認済みの期間を具体化する開発側の設計案であり、再認証条件・Google側二段階認証の実証方法・招待の不達等の詳細手順を確定したものではない。
