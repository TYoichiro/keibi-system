# 実装前レビューと不足資料の案内

作成日: 2026年10月8日（日本時間） / 版: 0.1

**確認結果: 初回の機能範囲と基本設計は整理されているが、業務の例外・認証運用・API/画面の具体的な契約に未決事項がある。今回の補足資料をそのまま承認済み仕様として実装せず、該当段階の判断を確定してからAI Agentへ渡す。今回は実装を行わない。**

調査対象はREADME、DEVELOPMENT、SECURITY、60項目のチェックリスト、初回要件書/データ設計案、管理者/警備員の業務フロー、フロントの画面・サンプル、既存API・DB接続・CI。既存の未コミット資料を前提にレビューした。画面の見た目の再検証や法的適合性の判定を行ったレビューではない。

## 1 整理できていること

- 初回はログイン・会社分離・隊員/取引先/現場・配置確定・本人予定。勤務希望・打刻・勤怠・報告・通知等は次期。
- 対象業務は交通誘導・施設警備。人数がそろってから確定し、一部だけ先に本人へ公開しない。
- 会社管理者・管制担当・閲覧者・警備員の4役割と、会社/拠点/本人の基本範囲。勤務開始後の変更は会社管理者。
- 本店と支店の独立した初期10人枠。在籍・休職を算入し、退職は履歴を残して枠から除外。担当者は個別ログイン、初回の支店追加・増枠は課金なし。
- 現場と日別勤務、下書きと公開版、配置履歴と重複防止予約を分ける設計。夜勤・同時確定・会社ID付き参照・RLS・再送への配慮。
- 既存APIのOrigin/CSRF/入力/容量/頻度制限、秘密の分離、検証コマンドと、モック/未実装の境界。

上記には確認済み要件と技術設計案が含まれる。承認の有無の正本は[要件書4章](MVP_REQUIREMENTS.md)。RLS、認証基盤、再送処理等がすでに実装されたことを示すものではない。

## 5 次に進める順序

1. 認証・マスタ設計に関わるD03/D07/D08/D09と、APIの基本契約D11を具体化する。
2. 配置を作る前にD01/D04/D05/D06を確認し、状態変更と確定条件を固定する。
3. 本人表示を接続する前にD02/D14/D15を確認する。
4. 試験運用前にD10/D12/D13を記入し、法定書類・既存台帳・障害時の役割を確認する。
5. 明示的な実装依頼を受けた後、AI引き継ぎのP1〜P6の該当段階へ進む。各段階でD16の検証と受入を行う。

今回、認証サービスやクラウドの契約、モック改修、DB変更、テスト環境の導入、実装は行っていない。法令・認証候補の公式確認先と確認日は試験運用資料に記載した。法定名簿・教育/勤怠書類を初回マスタで置き換えた扱いにしない。
