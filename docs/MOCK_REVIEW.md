# 業務フロー・要件とモックの照合

確認日: 2026年10月8日（日本時間）

今回の依頼は見た目のすり合わせ用のモック修正。業務データの保存、認証、権限制御、通知、正式な配置条件の判定は実装していない。

基準は[初回要件書](requirements/MVP_REQUIREMENTS.md)、[画面仕様案](requirements/MVP_SCREEN_SPEC.md)、[データ設計案](requirements/MVP_DATA_DESIGN.md)、[状態遷移案](requirements/MVP_STATE_TRANSITIONS.md)。[管理者フロー](workflows/admin-workflows.md)と[警備員フロー](workflows/guard-workflows.md)は次期の全体業務も含むため、初回対象との区別に使った。未決事項の判断は今回行っていない。

## モックの見方

初回の流れは「設定 → 取引先・現場・隊員 → 配置 → 警備員の勤務予定」。登録・編集のリンクと日付・対象の選択は見た目確認のために動く。保存・確定・改訂・取消・利用者発行・増枠のボタンは表示のみで、押しても業務状態は変わらない。

| 表示例 | URL |
| --- | --- |
| 認証 | `/login`、`/account/activate`、`/account/reset`、`/account/mfa`、`/account/security` |
| 隊員 | `/officers/new`、`/officers/edit?officer=G004` |
| 取引先 | `/clients/new`、`/clients/edit?client=C002` |
| 現場 | `/sites/new`、`/sites/edit?site=S002` |
| 勤務枠 | `/assignments/new`、`/assignments/edit?site=S002` |
| 翌日の公開例 | `/assignments?date=2026-10-05&duty=D20261005-S002-D` |
| 夜勤の改訂例 | `/assignments/edit?duty=D20261005-S010-N&mode=revision` |
| 全体取消の確認例 | `/assignments/edit?duty=D20261005-S002-D&mode=cancel` |
| 本人の確定予定 | `/guard/schedule?date=2026-10-05` |
| 本人の勤務詳細 | `/guard/site?duty=D20261005-S002-D` |
| 本人の取消概要 | `/guard/schedule?date=2026-10-06` |

10/4のサンプルは従来の35名必要・32名配置案を維持する。初回の交通誘導・施設警備だけでは11現場・30名必要、公開例19名、下書き8名、不足3名。雑踏警備5名は次期参考であり、初回サマリーから除く。公開状態はモック用の例で、資格・在籍・時間重複の正式な判定を通過した記録ではない。

10/5のS002は必要3名・配置3名（G004・G005・G035）の公開例を管理画面と本人画面で共用する。未来の勤務見本を追加しても、基準日時2026/10/4 09:30は変わらない。次期の勤怠・日報・希望・通知・週間見通しは独立した参考サンプルで、この公開例に自動連動しない。

10/6のS002は勤務枠全体の取消例。管理者側の有効人数から除き、本人には日時・現場名・取消状態だけを表示する。集合場所・指示・業務連絡先の詳細は表示しない。

本店の登録枠は在籍37＋休職2＝使用39、上限50という増枠後の見本。初期10人と区別し、退職1人は履歴を維持して枠から除く。支店の0／10人は追加後のレイアウト見本で、支店所属の業務データはない。

## 残る確認事項と今回の境界

- 資格・責任者・確認記録の具体条件（Q06）、現場詳細の公開期間（Q07）、発行・復旧・MFA方式（Q09）、終了後訂正・保持運用（Q10）は未決のまま。画面上の条件は案として表示する。
- 通信失敗、更新競合、保存成否不明、ログイン失効等は将来の実装条件。今回のフォームは静的な見本で、それらの処理や正式な入力検証を実装していない。
- 給与・請求、契約書類保管、GPS・実地図、応援配置、教育の詳細管理は追加していない。既存の次期参考画面は検討用に残した。
- 認証・認可・テナント分離・業務API／DBは変更していない。UI上の公開範囲の調整はアクセス制御の完成を意味しない。
