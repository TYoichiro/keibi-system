# 警備員向け 警備員管理システムの業務フロー案

作成日: 2026年10月7日

更新日: 2026年10月8日（Google招待・連携変更承認・管理者復旧の担当を反映）

警備員本人は、勤務希望を伝え、指示された現場で勤務し、勤務実績と業務内容を報告します。

全体の流れは、勤務希望の提出 → 確定した勤務予定の確認 → 現場での勤務 → 出退勤と日報の報告 → 管制の確認結果の確認です。

以下は現在の画面構成を基にした業務フローの案です。現在のシステムはモック段階で、図にあるログイン・打刻・保存・提出・通知は今後実装する操作を含みます。会社ごとの報告方法や申請ルールは、別途決める必要があります。

管理者や管制担当の操作は、[管理者向け業務フロー](admin-workflows.md)を参照してください。現在の操作範囲は、[README](../../README.md)と[開発状況と実装ガイド](../DEVELOPMENT.md)に記載しています。

## 初回実装との対応（2026年10月8日追記）

以下の図は将来の全体業務を含む。初回の範囲・本人の権限は[要件書](../requirements/MVP_REQUIREMENTS.md)を優先し、[画面仕様](../requirements/MVP_SCREEN_SPEC.md)と[実装前レビュー](../requirements/IMPLEMENTATION_READINESS.md)を参照する。この追記時点では資料の準備のみ。その後の依頼で[モックの照合・修正](../MOCK_REVIEW.md)を行ったが、図の保存・打刻・通知等の詳細機能は実装していない。

| この資料の業務 | 初回に扱う範囲 | 次期または既存手段で扱う範囲 |
| --- | --- | --- |
| 1 勤務予定と指示の確認 | 各自のGoogleログイン、招待と初回Google連携、本人の確定予定・変更/取消概要、許可された勤務の現場情報 | お知らせ・既読/確認送信は次期。勤務可否や指示確認は既存の連絡手段 |
| 2〜6 希望・出退勤・報告・事故・申請 | 確定勤務の変更が必要なら管制へ既存手段で連絡 | システムでの提出・打刻・修正・添付・承認は次期。事故は既存の緊急連絡/記録手順 |
| 7 教育と資格 | 本人の資格基本情報の閲覧 | 研修予定・参加回答・受講管理・証明書/資料配信は次期、既存管理を継続 |
| 8 本人情報と通知設定 | 本人基本情報、Google連携・アプリセッションの確認、Googleの設定/回復案内、アプリのログアウト | 隊員連絡先の直接編集と通知設定は初回対象外。訂正/Google連携変更は管理者等に依頼 |

勤務希望・下書きは確定予定ではない。図の「指示を確認したことを伝える」は、初回にシステムの既読や承認を保存する意味ではない。

管理側は本店所属の会社管理者だけが支店追加/増枠を行い、取引先は会社共通の1件を各拠点の現場から参照することが確定した。これにより警備員が会社共通の取引先一覧を閲覧できるようにはしない。本人の許可された担当現場情報だけを表示する。異動後の過去予定/履歴をどこまで閲覧するかは回答待ちで、以下の閲覧案を確定扱いにしない。

## 用語と図の読み方

| 用語 | 意味 |
| --- | --- |
| 管制 | 警備員の配置や出勤状況を確認し、現場を調整する担当者や仕事 |
| 配置 | 誰が、いつ、どの現場で働くかを決めること |
| 勤務希望 | 本人が申告する、働ける日・時間や休みの希望 |
| 勤務予定 | 会社から指示された、確定した勤務の予定 |
| 上番と下番 | 現場での勤務を開始することと終了すること |
| 打刻 | 勤務の開始・終了などの時刻を記録すること |
| 申し送り | 次の担当者に伝える注意事項や引き継ぎ |

図は上から下へ読みます。四角は操作、ひし形は判断、丸い枠はきっかけや完了を表します。図はMermaid形式で記載しているため、GitHubやMermaid対応のMarkdownプレビューで表示できます。

## 1 勤務予定と現場の指示を確認する

出勤前に、現場・時間・集合場所・持ち物を確認します。勤務希望を提出しただけでは、勤務する現場は確定しません。

関連画面: ログイン・ホーム・勤務予定・現場情報・お知らせ

各自のGoogle OAuth 2.0＋OpenID Connectによるログインのみを使うことは確認済み。初回は管理者のアプリ利用招待とGoogle本人認証を確認し、内部利用者・本人の隊員記録へ連携する。Google認証が成功しても未招待・停止中の利用者は利用できない。通常は検証済みの正規化iss＋subで連携を照合し、メールやURLの隊員IDで本人を切り替えない。招待とGoogle連携の詳細は[Google認証設計](../requirements/GOOGLE_AUTH_DESIGN.md)を参照する。

会社管理者から本人Googleメールへ届いた招待リンクを使う。リンクは発行から7日間有効で、再招待されたら旧リンクは使えない。期限切れ・不達等は会社管理者へ確認する。不達/誤宛先時の具体的な対応や本人確認証跡等はD09で引き続き決める。

初回に使えるのは個人Gmailと会社のGoogle Workspaceのアカウント。非Gmailかつhdなしの外部メールGoogleアカウントは対象外。Google側の二段階認証は警備員・管制・閲覧者に推奨し、会社管理者には必須とする方針が確定している。管理者の確認/強制方法とamr等の情報欠落時の扱いは技術未決である。

```mermaid
flowchart TD
    A([勤務前の確認]) --> B[Googleでログイン]
    B --> J{招待・Google連携と利用許可が有効?}
    J -- いいえ --> K[招待・利用許可を会社担当者へ確認]
    K --> B
    J -- はい --> L[本人の勤務予定・お知らせを開く]
    L --> C{配置が確定している?}
    C -- いいえ --> D[管制に確認して確定連絡を待つ]
    D --> C
    C -- はい --> E[勤務時間・集合場所・持ち物・指示を確認]
    E --> F{勤務できる?}
    F -- いいえ --> G[早めに管制へ連絡して調整]
    G --> B
    F -- はい --> H[指示を確認したことを伝える]
    H --> I([出勤準備完了])
```

`/guard/login`のGoogleボタンは現在表示のみ。固定サンプルの本人画面を開くリンクはモック閲覧用として分けている。自システムにGoogleのパスワード・二段階認証コード・バックアップコードを入力しない。Googleのセキュリティ設定と回復は公式サイトへ案内する。Googleログイン成功だけで二段階認証済みとは表示しない。共有端末ではアプリをログアウトし、Google側のアカウント状態も本人が確認する。アプリのログアウトはGoogle全体のログアウトではない。

全役割共通で、本人操作なし24時間、操作を続けても最長1か月でアプリのログイン状態を終了し、Google再ログインを求める。画面の自動更新だけでは期限を延長しない。1か月の技術案は作成時のJST翌月同日時（同日がない月は月末同時刻）とし、UTC日時で保存する。本人操作でアイドル期限を更新しても最長期限は延長しない。

## 2 勤務希望を提出する

働ける日・時間と休み希望を会社に伝えます。

関連画面: 勤務希望

```mermaid
flowchart TD
    A([勤務希望の提出時期]) --> B[対象期間を確認]
    B --> C[勤務できる日・休み希望を選ぶ]
    C --> D[希望時間・補足を入力]
    D --> E[入力内容を確認して提出]
    E --> F{提出後に変更が必要?}
    F -- はい --> G[管制へ連絡・変更を申請]
    G --> H[変更結果を確認]
    F -- いいえ --> I[確定した勤務予定を待つ]
    H --> I
    I --> J([配置の連絡を確認])
```

## 3 上番と休憩と下番を記録する

実際に勤務した内容を記録します。日付をまたぐ夜勤では、終了日の確認も必要です。

関連画面: 出退勤・勤務実績

```mermaid
flowchart TD
    A([現場で勤務を開始する]) --> B[対象の勤務を確認して上番報告]
    B --> C[警備業務を行う]
    C --> D[休憩時間を記録]
    D --> E[勤務終了時に下番報告]
    E --> F[開始・終了・休憩の記録を確認]
    F --> G{記録に誤りや漏れがある?}
    G -- はい --> H[打刻修正を申請]
    H --> I[修正結果を確認]
    G -- いいえ --> J([勤務記録の確認完了])
    I --> J
```

## 4 日報と申し送りを提出する

その日に行った仕事と、次の担当者が知っておくべきことを伝えます。

関連画面: 日報・申し送り・日報入力

```mermaid
flowchart TD
    A([報告するタイミングになる]) --> B[勤務日・現場を確認]
    B --> C[業務内容・異常の有無を入力]
    C --> D[次の担当者への申し送りを入力]
    D --> E[内容を確認して提出]
    E --> F[管制の確認結果を確認]
    F --> G{追記・修正の依頼がある?}
    G -- はい --> H[内容を修正して再提出]
    H --> F
    G -- いいえ --> I([報告完了])
```

## 5 事故とトラブルを連絡して報告する

緊急時は、安全確保と必要な連絡を先に行います。システムへの入力は、対応状況を記録するために使います。

関連画面: 事故・トラブル報告・連絡先・ヘルプ

```mermaid
flowchart TD
    A([事故・トラブルが発生]) --> B[安全確保・必要な緊急連絡を行う]
    B --> C[管制・現場責任者へ速やかに連絡]
    C --> D[指示を確認して必要な対応を行う]
    D --> E[対応が落ち着いてから報告内容を入力]
    E --> F[日時・場所・状況・対応を確認して提出]
    F --> G{追加の確認依頼がある?}
    G -- はい --> H[分かっている事実を追記]
    H --> F
    G -- いいえ --> I([報告・引き継ぎ完了])
```

## 6 各種申請を提出する

休暇・勤務変更・打刻修正・経費など、会社の判断や処理が必要な内容を申請します。

関連画面: 各種申請

現在のファイル選択は、選択したファイル名の確認のみです。資料のアップロードと保管、正式な経費精算は未実装です。

```mermaid
flowchart TD
    A([申請が必要になる]) --> B[申請の種類を選ぶ]
    B --> C[対象日・理由・必要な情報を入力]
    C --> D[必要に応じて証明資料を添付]
    D --> E[内容を確認して提出]
    E --> F[審査結果を確認]
    F --> G{結果は?}
    G -- 修正依頼 --> H[内容を修正して再提出]
    H --> F
    G -- 承認 --> I[変更・修正・精算の結果を確認]
    G -- 承認されない --> J[理由を確認して必要なら相談]
    I --> K([申請終了])
    J --> K
```

## 8 本人の連絡先と通知設定を更新する

会社が本人に連絡できる状態を保ちます。

関連画面: マイページ

以下の連絡先編集・通知設定は次期の業務。初回は登録された本人情報とGoogle連携を確認し、業務連絡先の訂正は会社担当者、別Googleアカウントへの連携変更は会社管理者へ依頼する。Googleの表示メールと業務連絡先は別項目で、メールの変更だけで認証連携は付け替えない。連携変更は本人確認と会社管理者の承認後、旧連携と全アプリセッションを失効し、新招待で再連携する。管理者本人の場合は自社の別管理者が承認し、他にいなければ運営者へ依頼する。Googleアカウントを発行してもらう手続きではない。

最初の会社管理者登録と全会社管理者がログイン不能になった場合のアプリ復旧/交代は、運営者が会社・本人を確認して対応する。Google側パスワード回復はGoogleへ案内し、アプリの復旧とは分ける。本人確認の具体的な証跡・受付・再有効化等の詳細手順はD09の未決事項に残す。

```mermaid
flowchart TD
    A([連絡先などが変わる]) --> B[マイページを開く]
    B --> C[電話番号・メール・通知設定を変更]
    C --> D[入力内容を確認して保存]
    D --> E[反映された内容を確認]
    E --> F{会社への連絡も必要?}
    F -- はい --> G[担当者へ変更を連絡]
    F -- いいえ --> H([更新完了])
    G --> H
```

## 今後の追加業務

給与明細の確認や正式な経費精算などは、現在のモックに含まれていない追加業務です。これらを扱う場合は、会社の運用と管理者側の処理に合わせて流れを整理します。
